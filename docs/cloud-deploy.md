# paper-radar 上云部署清单

> 状态：已确认执行｜创建于 2026-11-21｜本文件为新增，未改动 `docs/` 下任何既有文档

## 一、目标

让日报在**不需要本机开机**的前提下每期照常生成、发布、推送到 QQ 群；同时提供一个**同学可访问的网页控制台**，能改 prompt、领域、篇数、发送时间。

## 二、目标形态

```
阿里云轻量 (8.136.5.160, Ubuntu 24.04, 2C2G)
├── Caddy            :80  → 反向代理控制台
├── console.py       :8766 本机监听（加 Basic Auth）
├── main.py          systemd timer 每天 07:30
├── NapCat (Docker)  :3000 本机监听，QQ 小号常驻
└── swap 2G          防 OOM

外部依赖：DeepSeek API · GitHub Pages（已有）· QQ 群 759980091
```

## 四、决策记录

### D1 用纯净 Ubuntu 24.04，不用宝塔镜像
- **结论**：重置系统为 Ubuntu 24.04 LTS。
- **理由**：宝塔面板本身占 100–200MB 内存，2G 机器上会挤压 NapCat；且面板公网暴露是额外攻击面。这个项目的运维动作固定（起服务、看日志、跑定时），命令行完全覆盖。
- **代价**：排障只能 SSH。已通过 `systemd` + `journalctl` + 项目自带 `logs/run.log` 缓解。

### D2 SSH 用密钥对，不用密码
- **结论**：ed25519 密钥对，公钥绑定阿里云，私钥仅存本机。
- **理由**：密码会经过对话与剪贴板；密钥不泄露内容即可长期复用。

### D3 控制台走 IP + 端口，不做域名与备案
- **结论**：`http://8.136.5.160/`（Caddy 80 端口反代 8766）。
- **理由**：域名需 ICP 备案 2–3 周，当前需求（几个同学用）不值得等。
- **风险**：HTTP 明文。**必须**加 Basic Auth，且密码不能与其它服务复用。

### D4 QQ 推送搬上云（接受封号风险）
- **结论**：NapCat Docker 常驻，使用**小号**，不使用 1748000533。
- **理由**：用户明确要求「不等开机自动发」。
- **风险**：异地登录验证、掉线、封号。缓解：固定 IP、减少重启、失败写日志并保留待发队列。

### D5 代码通过打包上传，不依赖服务器直连 GitHub
- **结论**：本地 `tar` 打包 → `scp` 上传 → 服务器解包。后续更新用 `publish` 的 API 通道。
- **理由**：国内节点访问 `github.com` 不稳定（项目计划 §18.3 已记录），`git clone` 可能失败。

### D6 同学权限：可写（含 prompt）
- **结论**：按用户要求，同学可改 prompt、领域、篇数。
- **风险**：推荐标准会漂移；所有 LLM 消耗由用户承担。
- **缓解**：控制台写操作记入 `logs/console-audit.log`；每日运行前自动备份 `prompts/` 到 `prompts/.history/`。

## 六、回滚方案

| 场景 | 动作 |
|---|---|
| 服务起不来 | `systemctl status` + `journalctl -u paper-radar-console -n 100` |
| 想退回宝塔镜像 | 阿里云「重置系统」选回宝塔（会清空数据，先做快照） |
| 控制台被扫 / 被刷 | Caddy 加 IP 白名单，或 `systemctl stop paper-radar-console` |
| QQ 号被限制 | 停 NapCat 容器，改用「本地补发」模式（计划 §18.1） |
